## 一、统一 ID 与状态规则

| 标记 | 含义 |
|---|---|
| E | 已有组件，保留原 ID |
| D | 已有组件，需要深化 |
| N | 全新知识条目 |
| R | 关联知识，不重复建立主条目 |

**知识 ID 格式：**

```text
K-D01-001

K       = Knowledge
D01     = 知识领域
001     = 领域内永久编号
```

**五种知识对象：**
- BASE：基础组件
- COMPOUND：复合组件
- PATTERN：交互模式
- BUSINESS：业务组件
- ENGINEERING：工程专题

## 七、本批次需要特别保护的内容

1. 原有 Button、Input、Form、Table 等组件不能因新目录而重新生成一份重复组件。
2. 原有组件的历史 ID 必须保留，K-Dxx-xxx 仅作为知识目录 ID。
3. 同一个组件可以关联多个领域，但只能有一个主归属。
4. HTML 原生控件、复合组件和交互模式不能混为一类。
5. 一个组件的不同状态不能重复计为多个独立组件。
6. 尚未实现的功能不能标记为已完成。

本批次参考了 Radix UI、W3C WAI-ARIA APG 的组件及交互规范，尤其关注键盘操作、焦点管理、弹层行为和表单语义。

### D06 状态矩阵

所有适用组件都要检查以下状态：

| 状态            | 演示要求     |
|-----------------|--------------|
| Default         | 正常显示     |
| Loading         | 正在处理     |
| Success         | 操作成功     |
| Warning         | 需要注意     |
| Error           | 操作失败     |
| Empty           | 暂无数据     |
| Disabled        | 当前不可操作 |
| Offline         | 网络不可用   |
| Pending         | 等待处理     |
| Partial Success | 部分成功     |
| Conflict        | 数据冲突     |
| Recovery        | 正在恢复     |

不能要求每个组件都具备全部 12
种状态。例如，一个静态分隔线没有网络失败状态。应按组件适用性制定状态矩阵。

### D06 综合实训：批量订单处理异常恢复

个数据版本冲突。

**验收重点：**
不能重复处理已经成功的订单，也不能在冲突未解决时覆盖新数据。

显示流程执行状态。

的真实生产业务。通用流程图、节点编辑器与 BPMN 流程执行引擎必须区分。

具体接口和模型能力在真正实施时再核对最新版本，不能提前固定未经验证的
API。

- E、D、N、R 是目录状态标记；不能据此声称代码实现已经完成。
- 目录条目数量不等于新增代码组件数量。

## 2. D05 特别说明

- Table、Data Grid、Pivot Table、Tree Table、Virtual Grid 是不同概念。
- D05 的高级网格条目围绕 Data Grid 建立关联教学，不意味着每一项都需要制作一套互不相关的完整表格。
- Data Grid 实训覆盖多字段排序、组合筛选、列配置、批量编辑、分组聚合、复制粘贴、导出、虚拟滚动、持久化、并发和失败处理。
- PC 使用数据网格，手机使用适合触屏的替代布局。

## 3. D06 特别说明

- 组件状态矩阵包括 Default、Loading、Success、Warning、Error、Empty、Disabled、Offline、Pending、Partial Success、Conflict、Recovery。
- 不要求每个组件都具有全部状态，应按组件适用性制定状态矩阵。
- 批量处理实训中 20 个订单：15 个成功、3 个失败、1 个等待重试、1 个数据版本冲突。
- 不得重复处理已成功订单；冲突未解决前不得覆盖新数据。

## 4. D07 特别说明

- 交互测试必须覆盖鼠标、键盘、Escape、外部点击、焦点进入和恢复、边缘避让、多浮层层级、移动端触控及异步提交。
- Dialog、Menu、Combobox 等交互模式必须遵循键盘与焦点规则，不能只根据视觉效果验收。

## 5. D09 特别说明

- 地图坐标、路线计算和地图瓦片是不同能力。
- 演示可以使用固定数据；真实导航路线需要路由服务；真实定位需要用户授权；地图数据涉及服务商许可和调用成本。

## 7. D11 特别说明

- 图形展示工具、图形编辑器和流程执行引擎必须区分。
- React Flow 节点编辑器不等于完整 BPMN 流程执行引擎。
- 广告订单生产流程实训先实现流程编辑和模拟运行，不直接接入 ERP 的真实生产业务。

## 8. D12 特别说明

- 每个业务模块必须说明输入数据、处理规则、输出结果和关联记录，不能只做一个能点击的界面。
- 补料申请需要理解申请原因、次数、原订单关联、状态回退和后续生产恢复。

## 9. D13 特别说明

- 不同用户不能错误覆盖对方的数据。
- 断线重连后能正确同步。
- 用户身份与修改记录准确关联。
- 模拟光标移动不能冒充真实协同编辑。
- OT、CRDT 必须分别讲清楚，不能当作同一种算法。

## 10. D14 特别说明

- 仅有对话界面不等于 Agent。
- 能调用工具不等于具备自主决策权限。
- 能读取文件不等于有权修改文件。
- 生成报价不等于可以直接向客户发送。
- 订单修改、付款、删除、发布等操作必须设计权限与人工审批机制。
- Agent 记忆、模型上下文和业务数据库是不同概念。
- 具体接口和模型能力在真正实施时再核对最新版本，不能提前固定未经验证的 API。

## 11. D15 特别说明

- 不允许仅把中文字符串替换成英文，而不考虑布局变化。
- 不允许仅通过改变颜色模拟无障碍。
- 所有交互组件必须具有合理的键盘操作。
- 必须同时进行自动化检查和人工辅助技术测试。

## 12. D16 特别说明

- 必须有能够运行的代码示例，不能只展示技术名词。
- 必须覆盖失败和恢复，不能只演示成功流程。
- 必须区分前端控制、服务端控制和数据库保证。
- 前端隐藏按钮不能冒充真正的权限控制。
- 数据一致性必须说明并发和异常条件。
