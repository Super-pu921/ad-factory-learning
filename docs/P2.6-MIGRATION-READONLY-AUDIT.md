# V8 P2.6 — Migration Read-Only Static Audit

## Scope

This is a **static catalog validation tool**, not a migration implementation, authorization, or user-data audit. It runs on Node.js 22 with built-in modules, and reads only `data.json`. It does not access `localStorage`, IndexedDB, the network, or any user profile.

New files only:

- `scripts/migration-audit-core.mjs` — pure validation logic.
- `scripts/audit-v8-migration.mjs` — read-only CLI, JSON to stdout.
- `scripts/test-v8-migration.mjs` — synthetic memory fixtures and actual catalog assertions.
- `docs/P2.6-MIGRATION-READONLY-AUDIT.md` — this documentation.

## Report contract

`audit-v8-migration.mjs` prints one UTF-8 JSON object on stdout; errors go to stderr. Exit code `0` means static checks passed, **not** migration permitted. Exit code `1` means the static catalog failed or could not be read. The report includes a SHA-256 of the raw bytes of `data.json` (not a Git blob hash), `generatedAt`, baseline counts, structured checks, warnings, T01–T16 and `migrationReadiness`.

- `PASS` — supported static test actually executed and passed.
- `FAIL` — executed static test did not pass.
- `BLOCKED` — cannot perform without missing real-world prerequisites.
- `NOT_RUN` — no implementation/test execution.

T01–T03 are **independent static-only** checks with explicit `evidenceChecks`:

- **T01** (`C01`): parsed source contains the required root arrays. A file read/JSON parse failure makes T01 FAIL and leaves dependent T02/T03 BLOCKED.
- **T02** (`C03`): legacy ID type/uniqueness and phase identifier integrity; blocked if T01 fails.
- **T03** (`C02`, `C04`, `C05`, `C06`, `C07`): catalog size, stage coverage, references, quiz, metadata; blocked if T01 fails. A quiz-index failure must not incorrectly fail T01 or T02.

These tests do not prove data migration, user-record backups, or production readiness. T04–T09, T11–T16 remain NOT_RUN. T10 remains BLOCKED due to missing P1.3 original browser data audit.

The static catalog's original lesson/component association directions are not interchangeable. Any asymmetry is a `W01` review warning rather than a failed foreign-key check. Legacy numeric `resourceId` references are not asserted as official foreign keys: all 33 `resources` lack explicit stable IDs in the audited baseline; `W02` requires review before mapping.

**Production migration readiness is always BLOCKED**, even if all static checks pass, because P1.3, verified mappings, migration engine, and release approval are missing.

## Safety and rollback

Only file read APIs and pure functions are used. No real user records or browser storage are accessed. To roll back, after inspecting and approving the file list, remove **only** these four newly added files. Never use `git reset --hard` or clean the repository. Do not create commits, PRs, merges, or releases without separate approval.
